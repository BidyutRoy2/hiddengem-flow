    Window mode New

    Choose how the Flow opens when you click the toolbar icon — one setting, three modes. Switching closes the current surface.

    Default is Floating window — existing users see no change until they pick another mode. No new permission for any mode. From the floating window, switching to Side Panel sets the mode and asks you to click the toolbar icon once (Chrome needs a real click to open a panel).

    Floating window

    Click the HiddenGem Flow toolbar icon on any website to open the draggable floating window — or dock it as a side panel, or open it as a popup window, from the Window mode card above. Drag it by its header — its position is remembered.

    The window runs in a Shadow DOM, so the site's own styles cannot break it.

    What this extension does

    Daily Tasks — save the sites you open every day and open them all in one click. Scripts — a userscript manager: write or import scripts, scan them, and run them on the sites they match. Script Store — the Official Store on GitHub: load it, search it, install a script with one confirm. Notepad — quick local notes with brand, tags, pin and search — the same notes as the floating window. Flows — one routine = tasks + scripts + note, run with one click or on a schedule. Logs — per-tab status for every tab the extension opens, with Stop All.

      Scripts

      This site already has an official script — add it in one click from Script Store.

      A userscript manager: create, import, run, back up, delete and upgrade userscripts. Scripts run through Chrome's chrome.userScripts API — only on pages where you enable them, and only on the sites their @match lines name. Chrome also needs site access for those sites (a registered script without it never runs): click Grant site access on the script below, or set Site access → On all sites in the extension details.

      User scripts are not enabled yet.

      The userScripts permission alone is not enough — Chrome also needs you to flip a per-extension toggle:

      1. Open chrome://extensions
      2. Find HiddenGem Flow → Details
      3. Turn Allow User Scripts ON
      4. Reload this page — and reload any page where you want scripts to run

      Without that toggle, scripts are saved but never run, and nothing fails silently — this banner stays until the toggle is on. The button below only opens the Details page; no extension can flip the toggle for you.

      Checking whether user scripts can run…

      Chrome's "Allow User Scripts" toggle is Chrome's own — this extension cannot flip it. Open the extension details, turn the toggle ON, then run the self-test: a tiny script changes the active tab's title, so you can see for yourself that scripts run.

      GM functions that actually work: GM_setValue, GM_getValue, GM_notification, GM_addStyle, GM_xmlhttpRequest (only with @grant GM_xmlhttpRequest and the host in @connect), GM_setClipboard (and the GM.* object form). Not supported: GM_openInTab, GM_download, unsafeWindow and every other GM_* function — a script that calls one gets a scanner warning at install and a runtime error on the page, never a fake that pretends to work. GM values are stored in the page origin's localStorage, namespaced per script — the page can read them, so never store secrets with GM_*. Only JavaScript userscripts can run in a browser page: a file in another language can be opened here to inspect it, but it cannot run as a script.

                                What “running” means: chrome.userScripts registration is per-extension, not per-tab — a run is “running” when the matching scripts are registered and the tab was opened by this extension.                                   Permissions in use: storage, tabs, scripting, activeTab, userScripts, notifications, sidePanel, contextMenus, alarms. Optional only: tabGroups (“View and manage your tab groups”, asked once when grouping is used) and site access (*://*/*). No required host permissions — the floating window is injected only when you click the toolbar icon. Keyboard shortcuts need no permission (manifest commands). The omnibox keyword flow needs no permission either (manifest key only).
                                  
          
                                    
            
                                  • Scripts need two more grants, both yours to give. First, Chrome's per-extension Allow User Scripts toggle (chrome://extensions → HiddenGem Flow → Details) — no extension can flip it for you; the floating window has a button that opens that page directly. Second, site access for the sites a script runs on — an optional permission (*://*/*) granted per site (Scripts tab → Grant site access, or Site access → On all sites in the extension details). Until both are on, scripts are saved but never run.
                                    • 
            
                                  • Notifications are used by GM_notification from a running script, by the right-click menu and keyboard shortcuts (which confirm what they saved or ran), and by reminders — task reminders, the daily pinned-task nudge, scheduled Open All and note due dates. If notifications are blocked in Chrome, reminders are scheduled but cannot alert you, and the Flows tab says so instead of failing silently.
                                    • 
            
                                  • Alarms (alarms permission, no warning) drive the reminders: one alarm per task reminder, one for the daily nudge, one for scheduled Open All, one per scheduled Flow, one per note due date. Alarms wake the service worker only to fire — nothing runs in the background between alarms. Later: one alarm per enabled scheduled script (hgf-sched-…) and one for periodic sync (hgf-sync, only while sync is on with an interval).
                                    • 
            
                                  • Side Panel (sidePanel permission, no warning) docks the same floating UI at the side of the browser. Context menus (contextMenus permission, no warning) add the right-click menu. Neither permission shows a warning at install.
                                    • 
          
                                  
          
                                  Network: almost everything is user-triggered — nothing is sent to any server except (1) the best-effort favicon image (Google s2) shown next to each task site — a letter tile shows instead if it fails; (2) a script import from a URL, fetched once when you click Fetch, and the page you fetch can see the request; (3) Load store, which fetches the Official Store index (raw.githubusercontent, then jsDelivr), and opening a store script's detail view, which fetches its code once. The Smart Notification Bridge never fetches on its own — it reads the cached store copy. No analytics, no telemetry. The run log only records tabs this extension opened. The one exception is the update checker: it asks api.github.com for the latest release at most once every 6 hours (on startup/install and when this dashboard opens), plus whenever you click Check for updates below. It sends no data about you — the request is a plain public release listing. Later: (4) Sync — only when you turn it on and press Sync now (or set an interval): the backup payload goes to the provider you picked (your WebDAV server, api.github.com for Gist, googleapis.com for Drive), with the token you pasted.
