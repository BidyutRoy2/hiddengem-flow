◆ HiddenGem Flow — Store Uploader

Private tool for publishing scripts to the Official Store (hiddengem-flow-store) — straight from this page, or by hand with the download buttons. This page is a single file: open it from your own computer, no server, no account. Your browser talks directly to api.github.com; nothing goes through any server of ours. Your token is stored only in this page's localStorage in your browser, and is never written into this file.

1 · GitHub connection

No token saved in this browser yet.

Create the token (you do this on GitHub — this page cannot create it)

  1. GitHub → your avatar → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Token name: e.g. HiddenGem Flow store uploader. Expiration: pick one (90 days is a sane default).
  3. Repository access → Only select repositories → choose hiddengem-flow-store (and nothing else).
  4. Permissions → Repository permissions → Contents → Read and write. Nothing else is needed — do not add other permissions.
  5. Generate token, copy it once, paste it above, then click Test connection. A working token is saved in this browser's localStorage only; Forget token deletes it.

The token is sent only to api.github.com, in the Authorization header — never in a URL, never to any other host, never written into this file. If you would rather not use a token at all, skip this section: the Download buttons in step 2 still work and you can publish by hand on github.com.

    Honest limits
    
    
      
      
    • Only JavaScript userscripts can run in a browser page. A file in another language can be opened here to inspect it, but it cannot run as a script — this tool does not check the language of the code, and the store only lists userscripts.
      • 
      
    • A script with no @match lines will run nowhere until you add some.
      • 
      
    • Publishing writes to your repo with your token — the token can only do what its Contents permission allows, on the repo you picked. The first real publish is yours: this page was tested with a deliberately wrong token (which must fail plainly and publish nothing) and with no token at all (download fallback) — no real push was made from here.
      • 
      
    • jsDelivr cache clearing is best-effort: if a purge call fails, the publish itself still succeeded — Script Store may show the old index for a few minutes until the cache refreshes.
      • 
      
    • GitHub's own API limits apply (a few thousand requests per hour for a token). This page makes a handful of requests per publish.
