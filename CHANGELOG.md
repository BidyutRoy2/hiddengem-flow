## 1.2.1 — Open-tabs tracking on all four surfaces (dev build 2026-11-16, version 1.2.1)
- **NEW: open-tabs tracking (`entrypoints/shared/open-tabs.ts`, background-owned).** When a Daily Task site is opened FROM the extension — task-row click, Open selected, Open All — the background records the opened tabId against that taskId in `chrome.storage.session` under `hiddengemflow.tasks.open.v1` (taskId → tabIds, most recent last, max 50 per task). The map is session-only by design: it survives service-worker restarts (storage.session is not in-memory — the A-18 lesson) but resets on browser restart, and it is deliberately NOT in `BACKUP_DATA_KEYS`, so a snapshot can never carry tabIds and a restore can never resurrect them. The background also clears it explicitly on startup as a safety net. All map mutations run through one promise-chain mutex (the A-25 pattern) and fan the new map out to every tab's floating window; extension pages (dashboard, popup, side panel) get it through `storage.onChanged` on the session area.
- **NEW: ● Open badge + ✕ Close on every task row — all four surfaces.** Floating window (in-page, Shadow DOM), Side Panel, Popup (both via the shared `float-page.ts` module — implemented once there), and the Dashboard Daily Tasks list. An open task's row shows a green `● Open` badge (`● Open ×N` when N tabs are open from that task) and a red-outline `✕ Close` button, and the row gets the emerald border. Badge click focuses the tab (most recent first — never opens a new tab); Close closes ALL tabs tracked for that task by tabId, with no confirmation dialog (tabId targeting makes a wrong-tab close impossible by construction). The badge + close rendering is ONE shared helper (`createOpenBadge` / `createCloseOpenTabsButton` in `shared/open-tabs.ts`, createElement + textContent only, A-01 rule) used by all four surfaces; the in-page float's row code is a separate call site only because it lives in Shadow DOM.
- **NEW: URL-aware badges.** A tracked tab keeps its badge only while it is still on the task's SITE — `tabs.onUpdated` untracks a tabId the moment its URL stops matching the task URL (same-host check: hostname with one leading `www.` stripped, http/https treated the same, so a redirect or trailing-slash change does not false-trigger). A tab that navigates elsewhere loses its badge and can no longer be closed from the task row. `tabs.onRemoved` untracks immediately, so a manually closed tab drops its badge at once in every open surface.
